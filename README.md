# lab01-data-representation
# Лабораторна робота №1: Представлення даних у пам'яті комп'ютера

## 1. Мета роботи
Мета лабораторної роботи — експериментально дослідити, як комп'ютер представляє різні типи даних у пам'яті.

Під час роботи було перевірено:
* Скільки пам'яті займають основні типи C;
* Як числа представляються у десятковій, шістнадцятковій та двійковій формах;
* Як одна й та сама послідовність бітів може мати різну інтерпретацію;
* Як представляються знакові та беззнакові числа;
* Що відбувається на межах діапазону беззнакового типу;
* Як символи представляються числовими кодами;
* Як багатобайтові значення розташовуються у пам'яті;
* Який порядок байтів (endianness) використовує система.

**Головне питання лабораторної роботи:** Що насправді знаходиться в пам'яті комп'ютера, коли програма працює з числом або символом?  
**Відповідь:** Фізично в пам'яті завжди знаходяться тільки біти (послідовності нулів та одиниць). Значення цих бітів повністю визначається контекстом (типом даних), який використовує програма для їх інтерпретації.

## 📋 4. Результати експериментів та таблиці

### Завдання 1. Розміри типів даних (`types.c`)

| Тип | Розмір, bytes | Розмір, bits (bytes × 8) |
| :--- | :---: | :---: |
| **char** | 1 | 8 |
| **short** | 2 | 16 |
| **int** | 4 | 32 |
| **long** | 4 (MSVC Windows) / 8 (GCC Linux) | 32 / 64 |
| **long long** | 8 | 64 |
| **float** | 4 | 32 |
| **double** | 8 | 64 |
| **void \*** | 8 | 64 |

* **Чи всі типи займають однакову кількість пам'яті?** Ні, розмір залежить від типу даних та необхідного діапазону для зберігання значень.
* **Скільки бітів займає int у вашому середовищі?** 32 біти.
* **Який розмір має вказівник void \*?** 8 байтів (64 біти).
* **Що розмір вказівника говорить вам про архітектуру середовища?** Розмір вказівника 8 байтів (64 біти) свідчить про те, що система має 64-бітну архітектуру.

### Завдання 2. Decimal → Hexadecimal (`representations.c`)

| Decimal | Hexadecimal | Binary |
| :--- | :--- | :--- |
| **10** | 0xA | 1010 |
| **65** | 0x41 | 01000001 |
| **127** | 0x7F | 01111111 |
| **255** | 0xFF | 11111111 |
| **256** | 0x100 | 100000000 |
| **1024** | 0x400 | 10000000000 |

* **Чому 65, 0x41, 01000001 можуть представляти одне й те саме числове значення?** Тому що це просто різні символьні системи числення для відображення одного й того самого кількісного значення, що фізично зберігається в пам'яті.

---

### Завдання 3. Виведення бітів (`binary.c`)
* **Чому функція починає перевірку з біта 7, а не з біта 0?** При читанні чисел зліва направо ми звикли першим бачити найстарший біт (MSB), який для одного байта має індекс 7. Якщо почати з біта 0, бінарний код виведеться дзеркально.

---

### Завдання 4. Символ — це також число (`characters.c`)

| Character | Decimal | Hex |
| :---: | :---: | :---: |
| **A** | 65 | 0x41 |
| **B** | 66 | 0x42 |
| **a** | 97 | 0x61 |
| **0** | 48 | 0x30 |
| **9** | 57 | 0x39 |

* **Що фактично зберігається у змінній `char c = 'A';`?** У пам'яті зберігається числове значення 65 (код ASCII). Графічний символ літери формується тільки в момент виведення на екран.

---

### Завдання 5. Signed та Unsigned (`signed_unsigned.c`)
* **Прогноз для -1:** Очікується бітове представлення `11111111` (`0xFF`) через використання додаткового коду (two's complement).
* **Пояснення комбінації 11111111:** Для `uint8_t` це число 255. Для `int8_t` через додатковий код це число -1. Значення повністю визначається типом даних (контекстом).

---

### Завдання 6. Дослідження межі unsigned integer (`overflow.c`)
* **Прогноз переповнення:** `255 + 1 = 0` у типі `uint8_t`.
* **Фактичний результат програми:** `0`
* **Пояснення результату:** Оскільки тип `uint8_t` обмежений 8 бітами, додавання одиниці до максимального числа `11111111` призводить до виходу розряду за межі байта (`100000000`). Процесор відкидає 9-й біт, залишаючи молодші 8 бітів рівними нулю (відбувається беззнаковий *wrap-around*).

---

### Завдання 7-8. Дослідження пам'яті та Визначення Endianness (`memory.c`)
* **Прогноз (Гіпотеза):** Варіант B (78, 56, 34, 12) через очікування Little-endian на архітектурі x86-64.
* **Фактичний результат програми:** 
  * byte 0 = 0x78
  * byte 1 = 0x56
  * byte 2 = 0x34
  * byte 3 = 0x12
* **Аналіз:** Адреси байтів послідовно зростають. За найменшою адресою знаходиться наймолодший байт (`0x78`). Це експериментально доводить, що система використовує архітектуру **Little-endian**. Число при цьому не змінюється, змінюється лише порядок фізичного розташування його частин у RAM.

---

### Завдання 9. Один набір бітів — різні інтерпретації

Для набору бітів `01000001`:
* **Hexadecimal:** `0x41`
* **Unsigned decimal:** `65`
* **ASCII character:** `A`

* **Письмове пояснення:** Комп'ютеру недостатньо знати лише біти, оскільки вони є абстрактною послідовністю перемикачів. Щоб визначити значення даних, процесору необхідний **контекст**, який задається через **тип даних**. Саме тип вказує, за якими правилами комп'ютер має застосувати архітектурну **інтерпретацію** до цих бітів (як до цілого, дробового числа чи тексту).

---

### Завдання 13. Підсумкове та додаткове завдання (`inspect.c`)
Програма приймає від користувача однобайтове число, виводить його у 4 форматах (перевіряючи символ на друкованість), а також досліджує 32-бітне значення `0x12345678` для динамічного та автоматичного обчислення порядку байтів системи на основі аналізу вмісту першого байта в пам'яті.

## ❓ 14. Контрольні питання

1. **Що таке біт і байт?**  
   *Біт* — найменша одиниця інформації в ЕОМ, яка може приймати значення 0 або 1. *Байт* — базова адресована одиниця пам'яті, що складається з 8 послідовних бітів.
2. **Скільки різних значень можна представити за допомогою n бітів?**  
   За допомогою \(n\) бітів можна представити \(2^n\) унікальних значень.
3. **Який діапазон має 8-бітне unsigned integer?**  
   Від 0 до 255 (\(2^8 - 1\)).
4. **Який діапазон має 8-бітне signed integer у two's complement?**  
   Від -128 до +127.
5. **Чому hexadecimal зручний для системного програмування?**  
   Він компактний і дозволяє легко бачити бітову структуру пам'яті "на око": один шістнадцятковий символ чітко кодує групу з 4 бітів (нібл), а два символи утворюють рівно один байт.
6. **Чим відрізняються 11111111 як uint8_t та як int8_t?**  
   Фізичний вміст пам'яті ідентичний, але при читанні `uint8_t` інтерпретує його як число 255, а `int8_t` (через логіку додаткового коду) — як число -1.
7. **Що відбувається після збільшення uint8_t зі значенням 255?**  
   Відбувається циклічне беззнакове переповнення (*wrap-around*), і значення скидається в 0, оскільки 9-й біт перенесення ігнорується процесором.
8. **Що фактично зберігається у пам'яті для символу A?**  
   Ціле число 65, яке є його числовим ідентифікатором у кодуванні таблиці ASCII.
9. **Що таке endianness?**  
   Це архітектурний порядок розташування байтів багатобайтних типів даних (наприклад, 32-бітних інженерних чисел) в оперативній пам'яті комп'ютера.
10. **Який порядок байтів використовує досліджувана x86-64 система?**  
    Порядок **Little-endian** (молодші байти записуються за меншими адресами пам'яті).
11. **Що означає sizeof(int)?**  
    Це вбудований оператор мови C, який повертає кількість байтів (зазвичай 4), які займає змінна типу `int` у поточному компіляторі та ОС.
12. **Чому одні й ті самі біти можуть представляти різні дані?**  
    Комп'ютерна пам'ять однорідна. Сенс бітам надає програміст, вказуючи тип даних, створюючи у такий спосіб контекст для коректної інтерпретації двійкового коду процесором.
